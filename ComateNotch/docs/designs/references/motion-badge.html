一、问题量化：小图标下「闪不动」的物理原因

徽标几何写在 600 设计空间，落地时整体乘 size/600（刻意不做 scaleEffect 整体缩放，那是为了让小图标不栅格化发虚）。于是所有描边、位移都随尺寸线性缩小：28pt 下系数 0.0467、30pt 下 0.05。这就是「大图看着很动、真机上像静止」的由来。

四、空闲态：振幅增强

空闲是五态里最安静的一档，增强原则是「可感知、不打扰」：把落到亚像素的涟漪线宽救回可辨区间，中心点呼吸抬一点下限（避免「消失」感），并让底弧做极缓的明暗呼吸 —— 幅度与速度都远低于等待确认，两态一眼可分。同样给两档，下方条带规则同上。

B

等待确认走方案 B（推荐）：参数加码 + 底弧整体明暗脉动（opacity .55↔1.0 / 0.8s）。理由是「等你确认」是五态里唯一要求打断你的一档，小尺寸下明暗脉动比细线位移可靠得多；空闲态一并按增强档（同样含底弧极缓呼吸）。
风险：底弧是面板里最大的一块饱和色，脉动幅度偏大时会「吵闹」；如觉得吵，可只取一半幅度（.55↔.78），落地时改一个常量即可。

A

只做参数加码，不动底弧：线宽 / 透明度 / 行程 / 浮起全部加大，形态与现在完全一致，改动最小、最保守，空闲态取增强档但不含底弧呼吸。
风险：没有解决「整体不动」这一条，小尺寸下提升有限 —— 而这轮反馈的正是「整体闪动太弱」。

C

更激进：在 B 之上把周期压到 0.9s、脉冲改三圈连发，做成明确的「警报」节奏。
风险：常驻高频闪烁在菜单栏区域容易烦人，也更容易触发系统无障碍告警。本稿未画，需要的话我补一版。

本稿如何验证：① 全部动画元素都是内联可渲染节点，无 <defs> 模板克隆（§8.1 踩过的坑）；② 关键帧条带用冻结时刻法定格 —— 置 animation-play-state:paused 并给 animation-delay 负值，量各时刻几何与 opacity；③ 内联 SVG 的数值属性一律带引号（避免 tokenizer 把 / 吃进属性值导致 r=0）。
