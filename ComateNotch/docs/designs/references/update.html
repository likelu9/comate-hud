本稿新增一个独立小窗（已落地于 Sources/UpdateWindow.swift）用于「有新版」时的完整信息呈现，并画清它与三个既有入口的关系。窗口 420 × 320 pt（内容区）、不可缩放、标题「Comate HUD 有可用更新」。下载入口为一排两个、官网优先：官网下载（主，品牌绿） + GitHub 下载（次选，描边）。数据源：GitHub Releases（releases.atom，changelog 即取自其 Release 正文的 <ul><li> 条目，按 新增/优化/修复 分组）。绿底主按钮配深墨 #0F0F11；禁用绿底改 55% 白。

0 · 形态与数据源（三条代码事实）

① 现状：无独立更新窗。 ComateNotch/Sources/UpdateChecker.swift 只负责「取最新 tag 并比版本」，没有窗口；状态分散在 菜单项三态、菜单栏图标右上角红点、设置窗口「通用」页三态 三处。
② 为何也要独立窗口？ 与登录窗同因：HUD 面板是非激活 borderless NSPanel，挂不了 sheet。当前三入口都只能「就地变文案」，装不下 changelog 这种多行内容——故新增本小窗承载「有新版」的完整信息；其余状态仍可只在入口就地表达。
③ 数据源： 版本来自 GitHub Releases 的 atom feed（https://github.com/likelu9/comate-hud/releases.atom，用 atom 而非 REST，避开共享出口 IP 的 60 次/时限额）；changelog 同样取自这个 feed 的 Release 正文——release.sh 发版时把 versions.json 的 changelog 逐条渲染成 <ul><li>🔧 修复 …</li></ul> 写进 Release 正文（type 三值映射：new → 新增 · opt → 优化 · fix → 修复），与官网同一来源。不在客户端拉 versions.json：官网那份在 comate.wpsgo.com 下、无会话返回 403。检测失败一律静默（增值信息不干扰主功能）。

1 · 更新提示小窗 · 四态 1:1（420 × 320）

四扇窗内容区同高 320pt（#updContent），自上而下：应用图标 56×56 → 版本行（本地 → 新，tabular-nums）→ 更新说明区块（3 组圆点列表）→ 按钮区（沉底对齐）。按钮区用 margin-top:auto 沉底，保证四态按钮基线一致。本稿新增 独立窗；styleMask 不含 .resizable。

入口动作触发结果
A · 更新红点
菜单栏图标 / 页脚齿轮		单击直接打开本小窗（有新版态）——红点本身就是「有新版本」的信号，无需再等一次网络检查。
B · 菜单项
「检查更新」/「检测到新版 vX」		单击已有新版（标题为「检测到新版 vX」）→ 打开本小窗；标题为「检查更新」→ 就地置「检查中」（红点/按钮禁用）→ 结果：有新版则打开本小窗并变「检测到新版 vX」，否则就地变「已是最新版本 vX」，失败则保持「检查更新」静默。
C · 设置「关于」/「通用」页
「检查更新」行		单击就地三态：检查中 → 已是最新 / 检测到新版（整行可点）；点「检测到新版」这一行 → 打开本小窗。不在设置窗口内挂 sheet（同因：面板/窗口架构）。
D · 小窗内的动作官网下载
主按钮 · 优先引导		跳官网下载页（与首页下载按钮同一地址，当前版本对应的 DMG）：普通用户无需看懂 Releases，是最短路径。不 ack —— 只有「跳过此版本」才把该版本记为已读。
GitHub 下载
描边次按钮		跳 GitHub Release 发布页（Release.url，即 releases.atom 里该条 entry 的链接，也是更新红点的版本来源）：兼顾开发者与内网用户习惯。两者同级同高（34）、官网占主位。
稍后关窗，保留红点与「检测到新版 vX」——下次仍提示。
跳过此版本记下该版本为已读（ack） → 红点灭、菜单项回「已是最新版本 vX」；只对该版本生效，更高版本会重新提示（shouldShowDot 的 acknowledged 语义）。

3 · 版式与色彩规则（与 KD / DESIGN.md 对齐）

按钮：主按钮高 34、次按钮高 30、圆角统一 radius.card 14、字 12.5pt/600；间距 8。主按钮 hover #22E0BB / pressed #00A98A。下载入口成对出现时两个都是 34（同高同宽、flex:1）；单独出现的次按钮才用 30——避免一排里一大一小。
绿底文字硬规则：品牌绿是亮色，白字压绿仅 ≈1.9:1 不可用 → 主按钮字一律 #0F0F11（≈9.8:1）；唯一例外是禁用态（底 rgba(0,212,170,.40) 已变暗，字改用 rgba(255,255,255,.55)，实测 computed 不为 #FFF）。
同屏饱和色 ≤ 2：本窗常态只有「品牌绿（按钮/新版本号）」+「一个状态色（失败态的 #FF6259）」；changelog 的分组标签与圆点刻意用中性灰，不让语义色溢出到装饰（P3）。
